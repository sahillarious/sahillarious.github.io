Buffalo Accident Risk & Resource Allocation

Reinforcement-learning-based emergency resource dispatch across Buffalo, NY

PPO Reinforcement Learning PyTorch Actor-Critic Python
GitHub →

Overview

Urban emergency response is often static and slow to adapt to real-time risk. This project addresses Buffalo, NY's roughly 10,000 annual traffic incidents by modeling resource allocation as a reinforcement learning problem — dynamically placing Police, EMS, and DOT (tow truck) units across the city to minimize response times and maximize coverage in high-risk zones.

Approach

Data & Risk Mapping

Real-world traffic incident data from the City of Buffalo Open Data Portal was mapped onto a 145-cell grid (500m × 500m per cell). Incidents were classified into three types — Property Damage, Injury, and Skyway/High-speed — and per-cell probabilities were calculated to define need levels (Low, Medium, High) for each accident type.

RL Framework

The allocation problem is modeled as an MDP. The state space encodes accident probabilities, available resources, current allocation, and per-cell resource limits. The action space is a three-part discrete action: action type (allocate/deallocate), resource type (Police, EMS, or DOT), and target grid cell. A PPO agent with an Actor-Critic architecture was trained for its stability on this complex control task, and benchmarked against a DQN agent and a random-allocation baseline.

Reward Design

Reward structure incentivizes meeting real need: a high reward (1000 base, scaled 3× in high-need zones) for fulfilling a cell's resource requirements, a penalty (−5 per unit) for leaving resources idle, and penalties for invalid actions like over-allocating (−2) or deploying from an empty pool (−20).

Results

PPO Agent ~793 Strategic clustering
DQN Agent ~−47,500 Hesitant / incomplete
Random Baseline −8,170 to −8,230 Wasteful / invalid actions

Future Work

  • Incorporating temporal variation (time-of-day, seasonal patterns, traffic flow) into risk modeling
  • Real-time traffic data integration for live response-time estimation
  • Hierarchical RL to better coordinate multiple resource types
